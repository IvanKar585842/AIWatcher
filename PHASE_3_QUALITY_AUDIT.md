# Phase 3 — клиенты внутри workspace

Вердикт: **PASS**

Фаза добавляет управление клиентами агентства. Один клиент принадлежит одному workspace. Сайт привязывается к одному workspace и одному клиенту. Старые мониторы без клиента остались без клиента. Планировщик, загрузка страниц, AI, Clerk, Stripe, домен и Vercel не менялись. Продакшен-база не мигрировалась.

## Что сделано

- Список, создание, переименование и удаление клиента только внутри workspace, к которому есть доступ.
- Карточка клиента: сайты, число активных, изменения за сегодня, последние 10 изменений.
- Привязка и отвязка сайта. Привязать может только владелец монитора (`userId`), и только если сайт ещё нигде не состоит или уже в этом же workspace. Чужой workspace получает отказ.
- Отвязка снимает только `clientId`. Workspace у сайта остаётся.
- Удаление клиента оставляет монитор, снимок и историю. `clientId` становится пустым, `workspaceId` не сбрасывается. Это прежнее правило внешнего ключа из Phase 1.
- Настройки: выбранный workspace показывает клиентов. Зритель (`VIEWER`) видит список и карточку, кнопка создания скрыта. Сервер всё равно отклоняет запись.

## Доступ

Неизвестный workspace, чужой клиент и недостаточная роль отвечают одинаково: `Not found`, 404. Зритель может читать клиентов и не может создавать, переименовывать, удалять, привязывать и отвязывать. Участник, администратор и владелец могут писать клиентов: права `clients.write` и `monitors.write` заданы в Phase 2.

Тела запросов проверяет Zod со `.strict()`. Мутации проходят через rate limit. Запросы Prisma фильтруют и `id`, и `workspaceId`. Сырого SQL с пользовательским вводом нет.

## Проверки

`scripts/test-workspace-clients.ts` прошёл, включая:

- создание клиента внутри workspace;
- отказ зрителю и постороннему;
- чужой `clientId` в этом workspace не находится;
- привязка своего сайта, отказ перенести сайт из другого workspace, отказ зрителю привязать и отвязать;
- второй монитор остался без клиента;
- удаление клиента сохраняет монитор, снимок, изменение и workspace;
- существующий монитор `https://example.com` не получил workspace и client.

Повторно прошли `scripts/test-workspace-auth.ts` и `scripts/test-tenant-foundation.ts`.

В браузере на `http://localhost:3000/dashboard/settings` локальный оператор открыл North Agency и создал клиента Acme Studio. Сервер ответил `POST /api/workspaces/.../clients 201`, список показал `0 sites`, карточка открылась с `0 active`.

## Что сознательно не вошло

- Экран не привязывает существующий монитор к клиенту. Это делает API по `monitorId`.
- Старые мониторы не распределялись по клиентам автоматически.
- Письма-приглашения, лимиты тарифов, SDK и проверка домена не начинались.
- Продакшен по-прежнему нужно мигрировать до деплоя кода, который читает таблицы workspace и client. `vercel.json` собирает проект через `npm run build` без `migrate deploy`.
