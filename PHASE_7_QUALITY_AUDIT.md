# Phase 7 — группировка тревог

Вердикт: **PASS**

Фаза уменьшает повторные тревоги по одному клиенту. Цепочка AI, провайдер, загрузка страниц, планировщик, Clerk, Stripe и доставка как механизм не менялись. Новых таблиц нет. Продакшен-база не мигрировалась.

## Что сделано

- Похожие изменения одного клиента за 30 минут не отправляются повторно в почту, Telegram и webhook. Совпадение смотрит категорию и начало текста, не весь сайт клиента.
- Если новая тревога важнее уже отправленной, она всё равно уходит.
- Изменение остаётся в истории. Внутри приложения запись по каждому изменению тоже остаётся.
- Список проблем workspace показывает одну строку и счётчик `similar`. Сбой проверки не смешивается с изменением цены. Другой клиент не попадает в ту же группу.
- Монитор без клиента группируется по-старому: только точный повтор того же сайта.

## Доступ

Группировка читает только уведомления этого пользователя и мониторы его клиента. Она не открывает чужой workspace и не меняет права.

## Проверки

`scripts/test-alert-groups.ts` прошёл: похожие цены складываются, другая категория нет, CRITICAL не глушится, другой клиент не глушится, история остаётся, example.com не привязан.

Повторно прошёл `scripts/test-workspace-sites.ts`: сбой и отдельное критичное изменение не склеились. `npm run build` прошёл.

В браузере у North Agency две похожие цены одного клиента показались одной строкой `2 similar` с важностью CRITICAL. Временные сайты после проверки удалены. Монитор https://example.com остался без workspace и client.

## Что сознательно не вошло

- AI не переписывался и провайдер не менялся. Группировка стоит перед отправкой, а не вместо анализа.
- Письмо по-прежнему не уходит, если почта на сервере не настроена. Правило только не шлёт повтор.
- Отчёт по клиенту и белый ярлык не начинались.
