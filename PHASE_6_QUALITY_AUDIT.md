# Phase 6 — подтверждение домена

Вердикт: **PASS**

Фаза даёт владельцу монитора способ доказать, что хост его, и оставляет отказ понятным. Загрузка страниц, планировщик, обход защиты, Clerk, Stripe, домен, Vercel и AI не менялись. Продакшен-база не мигрировалась.

## Что сделано

- Владелец создаёт одну проверочную строку для монитора. Её можно опубликовать тремя способами: TXT-запись `watchflowing-verify=...` на хосте, файл `/.well-known/watchflowing-verify.txt` с этой строкой, или meta-тег `watchflowing-verify`.
- Проверка смотрит только на хост URL монитора. Редирект не считается доказательством. Текст страницы, в котором случайно есть строка, тоже не считается. Принимается только точное совпадение DNS, файла или meta-тега.
- Перед запросом адрес проходит ту же проверку, что и обычный монитор: только публичный HTTP(S), без частной сети.
- Успех записывает метод и время. Повторная проверка без строки снимает подтверждение. Удаление проверки стирает строку.
- Статус отказа для блокировки, входа и robots.txt говорит прямо: Watchflowing не обходит этот отказ. Подтверждённый домен не меняет это правило. Детектор challenge по-прежнему срабатывает, даже если на странице есть meta-тег.
- Подтверждение не создаёт снимок и не вызывает загрузчик страниц монитора.

## Доступ

Создать, проверить и удалить может только владелец монитора. Чужой id отвечает 404. Тело запроса проверяет Zod. Проверка ограничена по частоте. В ответ об ошибке не попадает HTML страницы.

Миграция `20261114140000_domain_verification` применена только локально. Если таблицы нет, маршрут отвечает 503 и не ломает чтение монитора.
