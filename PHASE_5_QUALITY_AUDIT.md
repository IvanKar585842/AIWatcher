# Phase 5 — скрипт на своём сайте

Вердикт: **PASS**

Фаза добавляет лёгкий скрипт, который владелец ставит на сайт, уже заведённый как монитор. Это отдельный приёмник событий. Он не входит в загрузку страниц, не обходит Cloudflare и не заменяет планировщик. Clerk, Stripe, домен, Vercel и AI не менялись. Продакшен-база не мигрировалась.

## Что сделано

- Ключ `wfsite_` создаёт и отзывает только владелец монитора. В базе лежит хеш. Полный ключ возвращается один раз в фрагменте `<script src="/monitor.js" data-site-key="..." defer>`.
- `public/monitor.js` отправляет ошибку JavaScript и, если в теге задан `data-watch`, факт наличия или отсутствия этих селекторов. Не больше 8 событий за просмотр. Скрипт не читает cookies, storage, формы и текст страницы.
- `POST /api/ingest/site` не требует сессию Clerk. Чужой и отозванный ключ отвечают 404. Origin или Referer должен совпадать с хостом URL монитора. Селекторы форм, паролей и полей ввода отклоняются. Сообщение с паролем или номером карты заменяется на `error`. Лишние поля JSON отклоняются. Тело больше 2000 символов отклоняется.
- Сигнал не создаёт снимок и не создаёт запись изменения. Ошибки и пропавшие элементы за 7 дней попадают в список проблем workspace, если монитор уже в этом workspace.
- На странице монитора есть блок создания, поворота и отзыва ключа и последние сигналы.

## Доступ

Ключ не даёт читать чужой workspace и не доказывает право на монитор в API аккаунта. Установка и отзыв проверяют `userId` монитора. Неизвестный ключ и недостаточное право отвечают 404. Лимит приёма — 120 событий в минуту на ключ. IP посетителя не сохраняется.

Новая миграция `20261114130000_site_sdk` применена только к локальной базе. Если таблицы ещё нет, маршруты ключа отвечают 503 и не ломают загрузку страницы монитора. Список проблем пропускает сигналы, пока таблицы нет.

## Проверки

`scripts/test-site-sdk.ts` прошёл: хеш вместо ключа, отказ чужому, отказ другому хосту, отказ селектору поля, отказ лишним полям, три разрешённых сигнала, отсутствие снимка и изменения, сигнал виден только в своём workspace, отзыв ключа, example.com не назначен.

Повторно прошёл `scripts/test-workspace-sites.ts`. `npm run build` прошёл.

В браузере на странице монитора Example появился блок Site script. Создание ключа показало фрагмент со `/monitor.js`. Ключ после проверки отозван. `http://localhost:3000/monitor.js` отдаёт скрипт.

## Что сознательно не вошло

- Сигнал не отправляет письмо, Telegram и webhook. Это остаётся у обычных изменений страницы.
- Наблюдение за DOM ограничено выбранными селекторами и одним повторным просмотром за 4 секунды. Текст узлов не передаётся.
- Проверка владения доменом для серверного fetch не начиналась.
- Продакшен нужно мигрировать до деплоя кода, который читает `SiteToken` и `SiteSignal`. `vercel.json` по-прежнему собирает проект без `migrate deploy`.
